# Grazel Dependency Pinning — System Map

> Reference map of how Grazel produces the `*_install.json` lockfiles that Bazel consumes after
> `migrateToBazel`. Read-only mapping (2026-07-01), grounded by three parallel investigations and
> verified against the live `WORKSPACE` + `*_install.json` files at the repo root. File:line refs
> are as of branch `arun/dependencies-refactor`.

---

## TL;DR

- Grazel emits **one `maven_install(...)` rule per maven repo** (default `maven`, plus per-variant
  `debug_maven`, `test_maven`, … and aggregated tool repos like `ksp_maven`) into the generated
  `WORKSPACE`.
- Each rule points at a lockfile `maven_install_json = "//:<repo>_install.json"`.
- **Grazel does not author the lockfile JSON.** `rules_jvm_external` does. Grazel *triggers* pinning
  (`bazel run @<repo>//:pin`) and executes the generated pin script, which writes the JSON to the
  workspace root.
- The lockfile reference + the companion `<repo>_pinned_maven_install()` call are emitted
  **commented-out** on the first run, then **uncommented** by the pinner after a successful pin.
- Pinning is gated by `rules.mavenInstall.artifactPinning.enabled` (defaults **true**) and runs as a
  dependency of `migrateToBazel`.

## End-to-end flow

```
                          ┌─────────────────────── UPSTREAM (Gradle-side compute) ───────────────────────┐
 resolved deps ──► WorkspaceDependencies.mavenInstallRootArtifactsByVariant()   [MavenInstallRootArtifacts.kt]
                          │  (root selection + reachability + owner/override transform)
                          ▼
                   CandidateMavenRepo.pinInputs : List<ResolvedDependency>      [model/WorkspacePlan.kt]
                          │  carried in WorkspacePlan.repoPlan + WorkspaceRenderPlan.materializedRepoNames
                          ├──────────────────────────────┐
                          ▼                               ▼
   RENDER PATH: MavenInstallArtifactsCalculator     PIN PATH: PinMavenArtifactsTask
   .get(...) → Set<MavenInstallData>                reads WorkspacePlan/RenderPlan JSON
   [MavenInstallArtifactsCalculator.kt]             [PinMavenArtifactsTask.kt]
                          │                               │
                          ▼                               ▼
   WorkspaceBuilder renders maven_install(...)      ArtifactPinner.pinArtifacts(...)
   + maven_install_json="//:<repo>_install.json"    [ArtifactPinner.kt]
   (commented out until first pin)                       │
   [WorkspaceBuilder.kt → MavenRules.kt] ──► WORKSPACE    │ bazel run @<repo>//:pin --script_path=…
                                                          │ then run the script (Worker API)
                                                          ▼
                                            rules_jvm_external writes  <repo>_install.json  (root)
                                                          │
                                                          ▼
                                            ArtifactPinner.pin(WORKSPACE): uncomment
                                            maven_install_json + <repo>_pinned_maven_install()
                                                          │
                          ┌───────────────────────────────┘
                          ▼
   BUILD TIME: `bazel build //...` reads each <repo>_install.json (pinned resolution, no live
   coursier resolve) and <repo>_pinned_maven_install() wires @<repo>//... targets into the graph.
```

## 1. Produced artifacts — what lands on disk

**One `*_install.json` lockfile per `maven_install` repo, written to the workspace root.**

- Filename = `"${repoName}_install.json"` — `MavenInstallArtifactsCalculator.kt:106-108,160-162`.
- Repo name derivation (`Repository.kt:21-25`, `String.toMavenRepoName()`): default variant → `maven`
  (so `maven_install.json`); every other repo → snake_case + `_maven` suffix (e.g. `debug` →
  `debug_maven` → `debug_maven_install.json`).

Live examples at repo root:
```
maven_install.json                 (default "maven" repo)
android_test_maven_install.json
debug_maven_install.json
lint_maven_install.json
test_maven_install.json
ksp_maven_install.json             (aggregated tool repo)
```

**Grazel does NOT author these files** — `rules_jvm_external` does, via its `:pin` target / coursier
resolution. Grazel only triggers it. Verified lockfile shape (rules_jvm_external `version "3"`):

| Top-level key | Meaning |
|---|---|
| `__AUTOGENERATED_FILE_DO_NOT_MODIFY_THIS_FILE_MANUALLY` | banner sentinel |
| `__INPUT_ARTIFACTS_HASH` | hash of the requested input artifact set (drift detection) |
| `__RESOLVED_ARTIFACTS_HASH` | hash of the resolved set (drift detection) |
| `artifacts` | shortId → `{ shasums: { jar: <sha256>, … }, version }` |
| `dependencies` | resolved transitive edges |
| `packages` | package → target info |
| `repositories` | repo URL → artifacts served |
| `services`, `version` | misc / `"3"` |

The two `__*_HASH` blocks are how rules_jvm_external detects an out-of-date pin; mismatch fails the
build with `maven_install.json contains an invalid input signature and must be regenerated` — a
string Grazel watches for (`BazelLogParsingOutputStream.kt:65,67`).

Stale lockfiles for removed repos are deleted by `cleanupStaleMavenInstallJsons`
(`ArtifactPinner.kt:206-216`), keyed off the same `_maven_install.json` naming.

## 2. Execution / control-flow path

### Trigger & wiring (`TasksManager.kt`)
- `migrateToBazel` is an empty aggregator (`:205-210`, registered `:184`).
- `PinMavenArtifactsTask` is always registered (`:178-182`) but only hooked into the graph when
  pinning is enabled:
  ```kotlin
  if (grazelComponent.extension().rules.mavenInstall.artifactPinning.enabled.get()) {
      dependsOn(pinArtifactsTask)
      dependsOn(generateDownloaderConfigTask)
  }   // TasksManager.kt:192-195
  ```
  Gate flag defaults **true** (`MavenInstallExtension.kt:111-113`).
- Ordering is implicit via input-file providers (no explicit `dependsOn` on root-script gen): the
  pin task consumes outputs of `GenerateRootBazelScriptsTask` (the WORKSPACE), `ComputeWorkspacePlanTask`,
  and `FinalizeWorkspacePlanTask`, so it runs after them.

### Task → pinner (`PinMavenArtifactsTask.kt`)
- `@UntrackedTask(because = "Up to date check implemented manually")` (`:37`) — Gradle does no
  incremental check; the pinner decides at runtime.
- Inputs: three `@InputFile` `RegularFileProperty` (`PathSensitivity.RELATIVE`, `:50-60`) —
  `workspaceFile` (generated WORKSPACE), `workspacePlan` (JSON → `WorkspacePlan`), `workspaceRenderPlan`
  (JSON → `WorkspaceRenderPlan`).
- `action()` (`:62-71`) deserializes the two plans (`fromJson`) and calls
  `artifactPinner.pinArtifacts(workspaceFile, workspacePlan, workspaceRenderPlan, gradleServices, logger)`.

### ArtifactPinner internals (`ArtifactPinner.kt`)
Interface `:46-73`; impl `DefaultArtifactPinner` (`@Singleton`, `:87-92`). `pinArtifacts(...)`
(`:218-294`):
1. Start "Pin maven artifacts" `ProgressLogger` (`:227`).
2. `collectPinnableMavenInstallRepos(...)` (`:228-231`, defn `:328-338`): intersect
   `workspaceRenderPlan.materializedRepoNames` with `workspacePlan.repoPlan`, take each repo's
   `pinInputs`, drop empties → `Map<repoName, List<ResolvedDependency>>`.
3. `cleanupStaleMavenInstallJsons(...)` (`:232`).
4. `shouldRunPinning(...)` (`:234-240`, defn `:133-194`) decides repin:
   - **First run:** WORKSPACE still has the commented `#maven_install_json` marker
     (`PINNED_MAVEN_INSTALL_MARKER`, `:76`) → `true` (`:147-153`).
   - **Incremental:** set `fail_if_repin_required = True` (`failWhenOutOfDate`, `:115-122`), pick a
     probe artifact per repo (`selectPinStatusProbeArtifact`, prefers a direct non-override dep,
     `:340-343`), run `bazelisk build <MavenDependency> --nobuild` (`:166-180`); the
     `BazelLogParsingOutputStream.isOutOfDate` flag drives the decision; revert the flag to `False`
     in an `.also {}` (`:188-192`).
5. If repinning:
   - Per repo, choose target via `determinePinningTarget` (`:197-204`): `@unpinned_<repo>//:pin` if
     `<repo>_install.json` exists, else `@<repo>//:pin`.
   - `bazelisk run <target> --script_path=build/grazel/maven/<repo>_pin.sh` with `ignoreExit=true`
     (`:245-273`). **`--script_path` makes Bazel emit a runnable script, not run the pin inline.**
   - On all-success: `pin(workspaceFile)` uncomments the markers (`:97-104`), then submit one
     `PinningWorkAction` per script via the Worker API (`:279-283`).
   - On any failure: `throw RuntimeException("Failed to pin artifacts")` (`:288`).
6. If up-to-date: log "Skipping pinning artifacts as they are up-to-date", return (`:290-293`).

### The exec (`bazel/exec/Bazel.kt`)
- All bazel goes through `ExecOperations.bazelCommand(...)` (`:50-76`); launcher is **bazelisk**, with
  `--noshow_progress --color=yes` appended (`:58-64`). Working dir = root project.
- Effective pin commands:
  - probe: `bazelisk build @<repo>//:<group>:<name> --nobuild …`
  - emit script: `bazelisk run @[unpinned_]<repo>//:pin --script_path=…<repo>_pin.sh …`
  - **write the JSON:** the generated `<repo>_pin.sh` is executed directly inside
    `PinningWorkAction.execute()` (`ArtifactPinner.kt:362-375`) — *this* is what writes the
    `<repo>_install.json`, not the `bazel run` step.

### Concurrency (Worker API)
- Pin scripts run via `WorkerExecutor.noIsolation()` (`ArtifactPinner.kt:280-282`).
- `PinningWorkAction : WorkAction<Parameters>` (`:345-376`), injected `ExecOperations`,
  `Parameters.pinScript: RegularFileProperty`. Runs in the daemon process (shared working dir);
  Gradle joins the worker queue at task end.

### Safety / recovery
- WORKSPACE mutation is marker-guarded and reversible: `pin()` / `unpin()` (`:97-113`) +
  `failWhenOutOfDate()` toggling `fail_if_repin_required` (`:115-122`).
- `ensureSafeToRun(...)` (`:296-325`) is a recovery wrapper for *other* bazel-invoking call sites
  (not `pinArtifacts` itself): on `isOutOfDate && !isSuccess` it logs "Recovering maven install json
  corruption", `unpin()`s, deletes all `**maven_install.json`, retries once, then asserts.
- Out-of-date / corruption detection is centralized in `BazelLogParsingOutputStream` — scans stderr
  for rules_jvm_external error strings (`:58-71`), sets `isOutOfDate` on `flush()` (`:83-86`),
  suppresses logging after "Successfully pinned resolved artifacts for" (`:101-109`).

## 3. The generated `maven_install(...)` rule + build-time contract

Emitted by `StatementsBuilder.mavenInstall(...)` (`MavenRules.kt:77-167`), driven per repo from
`WorkspaceBuilder.kt:127-153`. Loads (`MavenRules.kt:96-97`):
```
load("@rules_jvm_external//:defs.bzl", "maven_install")
load("@rules_jvm_external//:specs.bzl", "maven")
```
Attributes Grazel writes (`MavenRules.kt:99-153`): `name` (omitted for default → `maven`),
`artifacts`, `repositories` (sorted), `jetify`/`jetify_include_list`, `fail_on_missing_checksum`
(always `false`), `resolve_timeout`, `excluded_artifacts`, `override_targets`,
`maven_install_json = "//:<repo>_install.json"`, `version_conflict_policy`, `fail_if_repin_required`
(`False` when pinning on), `additional_coursier_options` (default `["--parallel","12"]`).

**Multiple repos:** one rule per *variant/scope* (`MavenInstallArtifactsCalculator.kt:84-148`; only
the default `maven` repo receives the shared `externalArtifacts`/`externalRepositories` such as
Dagger and bazel-common, `:123-133`) plus *aggregated tool repos* (`:151-183`, e.g. `ksp_maven`).
Six `maven_install(...)` blocks confirmed in the live WORKSPACE.

**First-run commenting / uncommenting (the key handshake):**
`isMavenInstallJsonEnabled = artifactPinning.enabled && mavenInstallJson.exists()`
(`MavenInstallData.kt:19-23`, computed at calculator `:144-145,179`). On the first run the JSON
doesn't exist yet, so the `maven_install_json` attribute **and** the `pinned_maven_install` load/call
are emitted commented (`#`, `MavenRules.kt:138,157,162-165`). After a successful pin,
`ArtifactPinner.pin()` uncomments them (`:97-104`); `unpin()` re-comments for recovery (`:106-113`).

**Build-time consumption (two-pronged per repo):**
1. The `maven_install` rule reads `maven_install_json = "//:<repo>_install.json"` → pinned
   resolution, no live coursier resolve.
2. A companion load+call wires the pinned jars into the graph (`MavenRules.kt:156-166`), named per
   repo to avoid symbol collisions:
   ```
   load("@<repo>//:defs.bzl", <repo>_pinned_maven_install = "pinned_maven_install")
   <repo>_pinned_maven_install()
   ```
   so labels like `@maven//:androidx_activity_activity` resolve (label form generated in
   `MavenInstallStore.kt:30-39`).

> ⚠️ Not to be confused: the `pinned_maven_install = True` flag in `CommonRules.kt:85-95`
> (`WORKSPACE:67`) is grab-bazel-common's `bazel_common_setup` toggle — unrelated to Grazel's
> per-repo lockfile references.

## 4. Upstream input data model (Gradle-side compute)

### Two boundaries share one model
The same `pinInputs` model feeds two consumers differently:
- **Render path** — `MavenInstallArtifactsCalculator` (from `WorkspaceBuilder.kt:127`) → `MavenInstallData`
  → rendered `maven_install(...)` text. This carries the actual artifacts/versions/exclusions/repos
  the pinner resolves *against*.
- **Pin path** — `PinMavenArtifactsTask` does **not** read `MavenInstallData`; it deserializes the
  `WorkspacePlan`/`WorkspaceRenderPlan` JSON and reads `CandidateMavenRepo.pinInputs` directly for
  *which repos to pin* + *probe artifact* (`ArtifactPinner.kt:328-343`).

### Core data classes
- **`ResolvedDependency`** (`model/ResolveDependenciesResult.kt:43-108`) — atomic resolved artifact:
  `id` (`group:name:version`), `version`, `shortId` (`group:name`), `direct`, `dependencies`,
  `excludeRules`, `repository`, `requiresJetifier`/`jetifierSource`, `overrideTarget`,
  `processorClass`. `merge` (`:110`) OR's `direct`, unions deps, **intersects** exclude rules.
- **`ExcludeRule`** (`model/ExcludeRule.kt:21-25`) — `group`, `artifact`.
- **`OverrideTarget`** (`ResolveDependenciesResult.kt:146-150`) — `artifactShortId` + `MavenDependency` label.
- **`MavenInstallData`** (`MavenInstallData.kt:6-26`) — the rendered-rule model, one per repo (see §3
  for the fields it drives). `failOnMissingChecksum` is hard-coded `false`; `additionalCoursierOptions`
  defaults `["--parallel","12"]`.
- **Plan carriers** (`model/WorkspacePlan.kt`): `WorkspacePlan.repoPlan: Map<String, CandidateMavenRepo>`;
  `CandidateMavenRepo { kind, pinInputs: List<ResolvedDependency>, overrideTargets }`; `kind ∈ {VARIANT,
  AGGREGATED}`; `WorkspaceRenderPlan.materializedRepoNames` gates which repos render/pin.

### `MavenInstallRootArtifacts` — building `pinInputs` (`MavenInstallRootArtifacts.kt`)
`WorkspaceDependencies.mavenInstallRootArtifactsByVariant()` (`:10-35`) → per-variant
`List<ResolvedDependency>` via private `mavenInstallRootArtifacts(...)` (`:37-90`):
- **Root selection:** `DEFAULT_VARIANT`/`LINT_VARIANT` → all artifacts are roots; else only `direct`
  (`isMavenRootArtifact`, `:50-53,144`).
- **Reachability:** unions four reachable-shortId computations (scoped transitive, workspace
  transitive w/ excluded roots, promoted-root transitive, declared-graph BFS) minus the roots
  (`:60,76,92,103,116-142`).
- **Owner/override transform:** reachable shortIds resolved to an owning `ResolvedDependency`
  (`ownerFor`, `:167-180`). For `DEFAULT_VARIANT`, strip `overrideTarget` (`:80`); for other variants
  `asOwnerOverride` marks `direct=false` + assigns a per-variant `overrideTarget` (`:194-202`).
- Output: roots + transformed reachable, `distinctBy(shortId)`, sorted by `id`.

### `MavenInstallArtifactsCalculator` — `ResolvedDependency` → artifact list
Entry `get(layout, workspacePlan, externalArtifacts, externalRepositories, materializedMavenRepos)`
(`:77-186`). DSL config: `excludeArtifactsDenyList`, `includeCredentials`, and `overrideVersionsMap`
parsed from `dependencies.overrideArtifactVersions` (`:57-75`).
- VARIANT pass (`:84-148`): `pinInputs` + version-override coordinates injected via
  `ResolvedDependency.fromId` (`:93-98`), mapped via `toMavenInstallArtifact` (`:188-204`):
  version = `overrideVersionsMap[shortId] ?: resolved`; exclusions from `excludeRules` via
  `toExclusion` (`:216-221`, suppressed by `excludeArtifactsDenyList`); emits `SimpleArtifact` or
  `DetailedArtifact`. **No classifier/packaging handling — reduced to group:name:version (+exclusions).**
- AGGREGATED pass (`:150-183`): `pinInputs` directly, no version-override, no jetifier, empty overrides.
- Default-repo specialization (`:123-133`): `externalArtifacts`/`externalRepositories` attached only
  when name == `maven`.

### Repositories & credentials
- Gradle-side `Repository` model + `RepositoryDataSource` (`gradle/Repository.kt:31-137`): collected
  from `allprojects`, keeps `DefaultMavenArtifactRepository`, excludes maven-local; `isSupported` = no
  creds or basic-auth only.
- Calculator maps `supportedRepositories` → bazel `DefaultMavenRepository`
  (`MavenInstallArtifactsCalculator.kt:223-243`); username/password gated on `includeCredentials`.
- **`UrlRewriter`** (`migrate/dependencies/UrlRewriter.kt:24-40`): separate from the rule model;
  writes a Coursier credentials/url-rewrite file for repos that have *both* user+password
  (`rewrite <host><path>/(.*) <user>:<pass>@…`). This is the private-repo credential mechanism,
  written to disk.

### Overrides & exclusions — provenance
- `dependencies { overrideArtifactVersions = [...] }` (`RulesExtension.kt:36`) → both `overrideVersionsMap`
  (version selection) and injected synthetic direct artifacts.
- `rules { mavenInstall { … } }` (`MavenInstallExtension.kt:64-79`): `excludeArtifactsDenyList`,
  `overrideTargetLabels` (→ `override_targets`), `excludeArtifacts` (→ `excluded_artifacts`),
  jetify include/exclude, `versionConflictPolicy`, `includeCredentials`, `additionalCoursierOptions`,
  `resolveTimeout`, `artifactPinning.enabled`.
- Per-artifact exclude rules originate on `ResolvedDependency.excludeRules` (Gradle-resolved), not
  the DSL; `excludeArtifactsDenyList` only suppresses them.
- **Override targets — two origins merged** in `calculateMavenInstallOverrideTargets`
  (`MavenInstallOverrideTargets.kt:22-39`): DSL `overrideTargetLabels` (filtered to repo artifacts) +
  artifact-level `ResolvedDependency.overrideTarget`; self-overrides filtered out (`isExactSelfOverride`,
  `:41-49`). Artifact-level targets minted by `mavenOverrideTarget` (`OverrideTargets.kt:23-33`),
  pointing non-default-variant transitive artifacts at the per-variant maven repo
  (`MavenInstallRootArtifacts.kt:198-200`).

### Boundary into pinning (what crosses)
`PinMavenArtifactsTask` reads `WorkspaceRenderPlan.materializedRepoNames` (gate) +
`WorkspacePlan.repoPlan[*].pinInputs` (artifact list for probe/repin). The actual
artifact/version/exclusion/repo data the pinner resolves crosses via the **rendered rule text**, not
the plan JSON; the plan JSON carries only pin orchestration metadata + probe inputs.

## 5. Notable findings / gotchas

- **`ArtifactPinner.kt` filename was corrected** from its old misspelled
  form; the class remains `ArtifactPinner`.
- **Grazel triggers pinning; it does not author the JSON.** rules_jvm_external writes the lockfile by
  running the generated `<repo>_pin.sh`; `bazel run …:pin` only *emits* that script (`--script_path`).
- **`ClasspathReduction.kt` is misnamed** for the pinning topic — it holds `calculateMavenDependencyTags`
  / `calculateDirectDependencyTags` (BUILD-target tag-string generation), not classpath reduction. The
  actual root-artifact reduction lives in `MavenInstallRootArtifacts.kt`.
- **Classifiers / custom packaging are dropped** at the calculator boundary — artifacts reduce to
  `group:name:version` (+ exclusions) only.
- **`failOnMissingChecksum` is hard-coded `false`** in `MavenInstallData` (not DSL-driven).
- The commented-then-uncommented WORKSPACE handshake is load-bearing: a half-finished first run leaves
  the markers commented, which (correctly) makes the next run treat pinning as a first run again.

## 6. Local Maven resolution follow-up policy (Items 36-38)

The next optimization is not about the already-pinned happy path where `shouldRunPinning` skips
work. It targets the cold/changed pin path where `rules_jvm_external` would otherwise run Coursier
against remote repositories.

**Altitude contract:**
- `gradle/dependencies` owns Gradle fact hydration: artifact path index, component-id map, and
  `PomFileResolver`.
- The proxy owns HTTP serving/cache/write-through/stats only. It consumes file/path facts and the
  resolver interface; it must not read `Project`, `Configuration`, `ComponentIdentifier`,
  `ResolvedArtifactResult`, `ArtifactView`, or generated output.
- `PinMavenArtifactsTask` / `ArtifactPinner` owns the experiment-gated orchestration: configure
  proxy, swap WORKSPACE repos to localhost for the pin, run the existing pin flow, reconstruct
  lockfiles, validate, unswap.
- `MavenInstallLockfileReconstructor` is pure Kotlin: JSON + Starlark `repr` + rje 6.10 hashes only.

**Miss policy:**
- Resolved artifact requests (`.jar`, `.aar`, classifier jars, etc.) must be served from Gradle's
  artifact index. Missing resolved artifact = hard failure.
- POM requests for known Gradle-resolved components must be served by the lazy memoized
  `ArtifactResolutionQuery` resolver. Known component POM failure = hard failure.
- Unknown parent/BOM metadata POMs may fall back to origin, but the fallback must be counted and
  reported.
- Checksums are computed from the exact bytes served for the base path.

**Verification anchor:**
- `experiments.localMavenResolution` defaults false. Flag-off output must stay byte-identical.
- During the goal, flag-on verification must force the repin path locally and prove reconstructed
  lockfiles are byte-identical to vanilla pin baselines on sample and the clean committed PAX
  baseline.
- No localhost URL may survive in committed `WORKSPACE` or `*_install.json`.
- Proxy summaries must report Gradle artifact hits, Gradle POM hits, unknown metadata origin
  fallbacks, artifact misses, and elapsed time.
